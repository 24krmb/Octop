# 期货会员席位持仓分析规范

取得 MCP 返回的席位持仓数据后，按本规范自行写代码计算。不要调用通用统计 MCP，也不要把未经检查的截断、错位或跨口径数据直接送入统计过程。

## 目录

1. 数据准备与对齐
2. 席位排名
3. 增减变化
4. 净持仓
5. 集中度
6. 多空结构
7. 重点席位跟踪
8. 代码与结果检查

## 1. 数据准备与对齐

- 将 `get_futures_member_positions` 返回的 rows 解析为明确的 `(交易日期, 合约代码, 会员简称, 持仓类型)` 记录；先观察实际返回的字段名（中文 key），再按其取值。
- 将 `position_type` 归一化为 `volume / long / short` 三类，避免 `1/2/3`、英文、中文别名混用。
- 检查 `total`、`returned`、`truncated` 和 `hint`。序列被截断时缩小 symbol/contract/member_name 过滤后继续查询，不能直接在前 20 席位不完整的情况下计算集中度。
- 将缺失值保留为缺失，不用 0 填充持仓量、变化量或金额。
- 手数口径与金额口径分开，不合并排名、不合并集中度。
- 保留原始单位、合约代码和会员简称；派生结果另建字段，不覆盖原值。

## 2. 席位排名

- 只对同一交易日、同一合约、同一持仓类型排名；多头按多头持仓量降序，空头按空头持仓量降序，成交量单独排名。
- 每席位的占比 `share = value / total_of_type`，total 为该合约该持仓类型的会员合计，报告分母口径。
- 排名结果同时给出当日值、变化量和占比；并列时使用稳定排序并说明并列规则。
- 默认取前 N（5/10/20），报告 N；需要完整前 20 席位时确保返回条数 ≥ 20 且未截断。

## 3. 增减变化

- 优先使用接口返回的“变化”字段；与相邻交易日的原始值复核，防止换月、合约切换或字段口径不同。
- 分别计算多头增仓榜、多头减仓榜、空头增仓榜、空头减仓榜和成交量增减榜。
- 区分绝对手数增减与占比增减；大席位与小席位的手数增减不可直接比重要性。
- 连续跟踪时明确是单日增减还是区间累计；区间累计要用首尾原始值相减，不把每日变化简单相加后误称单日变化。

## 4. 净持仓

- 单合约净持仓 `net = long - short`（手数口径），金额口径净持仓额同理。
- 净多席位为正值，净空席位为负值；分别列出净多榜和净空榜。
- 单会员×单合约净持仓：会员可能只进入多头或空头一侧榜单，未进入的另一侧按 0 计算，并在结果中说明该侧未上榜、按 0 处理。
- 品种级净持仓用 `get_member_position_summary`，注意它是跨合约合并，不标注合约月份。
- 跨合约合并前说明是否合并了不同到期月份；不同到期月份的持仓结构可能完全不同，不要无说明相加。

## 5. 集中度

- 前 N 席位集中度 `CR(N) = sum(top N value) / total_of_type`。
- **分母口径**：`total_of_type` 应优先用**全市场该合约该持仓类型的总持仓**，从 `get_type_positions_amount` 或行情接口的持仓量获取。
  - `get_futures_member_positions` 只返回交易所公布的席位（通常前 20 名），其合计 ≠ 全市场持仓，直接用作分母会高估集中度。
  - 仅在确实拿不到全市场持仓时，才回退用席位合计作分母，并在结果中标注分母口径（脚本输出字段 `concentration_denominator`）。
- 用脚本计算时传入全市场持仓：`scripts/analyze_positions.py analyze --market-total <json>`，格式 `{"scope": {"long": .., "short": .., "volume": ..}}`，脚本会以全市场持仓作为 CR 分母。
- 分别计算 CR5、CR10、CR20，多头与空头分别计算；多头与空头集中度的不对称本身就是结构信息。
- 集中度变化要与历史比较（上周、上月或近 N 日序列），单日集中度只描述当前分布。
- 报告分母口径：全市场持仓、全部会员还是仅前 20 席位；口径不同不可直接互比。

## 6. 多空结构

- 前 20 席位多空持仓量比 `long_total / short_total`；大于 1 表示前 20 席位整体偏多，小于 1 偏空。
- 同时给出净持仓合计和多空合计，避免只看比值忽略规模。
- 多空结构变化要区分来自新增持仓、减仓还是换手，并指出是少数重点席位主导还是普遍变化。
- 可按席位类别（外资/机构/零售）分别汇总多空持仓与净持仓，观察哪类席位主导当前多空结构；默认分类口径见第 7 节，用户自定义时以用户为准。
- 会员席位结构反映席位层面的多空分布，与价格涨跌没有确定因果；不据此给出买卖建议或价格预测。

## 7. 重点席位跟踪

- 指定会员在指定合约上的建仓过程使用 `get_company_contract_opening_process`，按交易日升序观察多/空/净持仓及持仓均价演变。
- 持仓均价变化反映建仓成本方向，但与市场价格共同作用产生盈亏；不把持仓均价解释为盈亏唯一来源。
- 单席位方向用 `get_company_type_profit`（区间累计盈亏）和 `get_company_type_profit_series`（每日盈亏）辅助，盈亏与持仓方向同时使用。
- 会员简称先用 `get_futures_member_company_names` 标准化，避免简称/全称不一致导致漏查。
- 席位类别默认口径（用户未自定义时使用）：
  - 外资：瑞银期货、高盛期货、摩根大通
  - 机构：中信期货、华泰期货、国泰君安、海通期货、东证期货
  - 零售：徽商期货、东方财富期货、平安期货
  - 未列出的席位不强行归类；用户给出自定义分类时以用户为准。

## 8. 代码与结果检查

- 使用可审阅的 Python 或等价代码完成排序、集中度、多空比、净持仓和增减计算；保持原始数据与派生结果分离。
- 在计算前断言日期有序、关键字段存在、分母非零、持仓类型归一化正确且样本量满足要求。
- 对随机抽取的 2~3 个席位手工复核排名方向、占比、净持仓和增减方向。
- 输出使用的公式、样本范围、有效席位数和任何降级处理，使结果可复现。
