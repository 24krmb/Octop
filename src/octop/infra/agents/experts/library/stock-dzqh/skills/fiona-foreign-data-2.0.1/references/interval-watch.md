# 假期与自定义区间观察

用于假期中观察、节后复盘、区间观察报告和报告更新。普通品种／事件追问直接承接已有证据回答。行情参数和计算以 [共用行情口径](data-method.md) 为准。

普通区间表格先用 [共用行情口径](data-method.md)；生成文件时才读 [HTML 交付](presentation.md)，需要同期事件时才读 [资讯与编辑](editorial.md)，已读资料不重复加载。

## 窗口与场景

- “上周”默认按北京时间自然周，即上周一 00:00 至本周一 00:00；输出先列具体日期。用户指定交易周或其他口径时遵从。
- 用户明确的日期、年份、时刻优先；只给日期时取完整自然日，即开始日 00:00 至结束日次日 00:00，声明边界。不能把窗口外的下一交易日行情混入。
- 指定假期时核实交易所的实际休市、节前夜盘和首个复市时段。默认起点为国内节前最后交易日正常日盘结束时刻（常见 15:00，按实际安排），期中截止为用户指定或当前时间；完整复盘截止在首个恢复交易时段开始前，含可能恢复的夜盘。
- 只给日期区间时，只有与已核实假期休市日期完全等同时才用假期标题；部分重合、包含假期或未核实则用日期标题。用户明确给定的较短窗口仍照用，不擅自扩成完整假期。
- 工具不覆盖该年份／地区时可用交易所公告核实。无法核实日历不等于不存在假期：日期明确则按自定义区间继续并说明未核实；只有假期名称、窗口无法确定时询问。
- `scenario` 使用 `holiday`、`custom_interval` 或 `simulated_holiday`。模拟只是假设国内休市，行情、资讯、海外安排仍须真实；明确标注假设，不将其写成法定假期。
- 未来区间不能生成表现；历史区间先检查数据起点与实际覆盖。仅有历史资料时标明来源与是否独立核验，不用近期行情替换历史日期。

周报及普通自定义区间涨跌默认按窗口内首末原始记录，生成底稿显式设 `endpoint_mode: "in_window"`；假期累计或用户指定窗口前基准时设 `pre_window_anchor`。模式与 scenario 分开，不以修改 requested_start 或临时改写渲染器来绕过端点校验。

## 报告流程

1. 明确请求窗口和资讯截止时刻，取映射及原始行情统计。按共用口径验证基准、终值、实际时间、合约和单位，按外盘标的去重，保留多个国内关联。需要路径时再取序列。
2. 按所选端点口径比较涨跌与板块分化；窗口前基准缺失的项不能混入假期累计排名，窗口内模式逐项披露实际起点。百分比排名不是风险或机会排名，外盘映射不等于国内传导比例。
3. 用户只要涨跌表或纯行情报告时不额外检索新闻；需要事件与解释时，按 [资讯与编辑](editorial.md) 先宽扫宏观与商品大事，再核实明显波动的候选解释。逐条打开一手来源；保留国内重要政策和突发事件，不为每个涨跌强配新闻。历史时点报告只使用当时已知资料。
4. 采用“本期要点 → 外盘表现 → 重要事件 → 关联观察 → 来源与口径”。解释性正文通常 600—1000 字，约 3 条要点、3—5 个事件只是起点，无重大消息不凑数。全量行情及缺失项放在展开明细。没有已核实事件时隐藏事件章节，注明资讯未纳入，不用空章占位，也不据此声称该区间没有事件。
5. 按 [HTML 交付](presentation.md) 用模板和渲染器生成单文件 HTML，复核数值、引用、手机与打印展示，再交付文件链接和主要覆盖说明。用户指定其他格式则遵从。

仅有行情时生成行情版，仅有资讯时生成资讯版，明确缺口；两者都没有则说明缺少的来源。关联观察写本期变化、具体国内品种和必要条件，无内盘对照不判断外盘变化已被国内消化。不默认扩成库存、终端消费等深度基本面研究。

更新报告时保持原始基准与取价口径，重新查询截至最新已同步行情，核实新增资讯，另存新版本。原基准无法重新核验时可引用已有可靠底稿并说明，不能悄悄换基准；缺少底稿则披露限制。
