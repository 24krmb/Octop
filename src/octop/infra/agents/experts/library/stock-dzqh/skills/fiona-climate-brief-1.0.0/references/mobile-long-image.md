# 移动端结论长图

仅在用户要求移动端长图、传播海报、结论图、图片摘要或适合社交转发的版本时使用本文件。长图是对研究内容的重新编辑，不是完整日报、周报的纵向截图，也不取代用户同时要求的完整报告。

## 先确定传播任务

从用户请求或已有材料确定长图的研究时点、主题和受众，再从已核验材料中提炼一个主结论。只保留理解该结论所需的证据；完整来源、方法细节和次要地区可留在报告或链接中。没有现成报告时，仍按本 Skill 的来源与研究方法完成必要核验，不能为了视觉速度降低证据标准。

用户仅说“生成一份最新的移动端长图”或同等简短请求时，不追问其本可由 Skill 决定的版式参数，采用以下默认值：范围为全球气候态势及其对主要大宗商品的影响；资料截止到生成时刻；以最新有效气候状态为背景，重点筛选最近 7 个自然日的重要新增、修订与产业兑现；时区用北京时间；交付一个以 1080 px 为设计基准、可响应手机屏幕的中文单页 HTML。没有重大新增时如实呈现持续状态、分歧与下一验证信号，不制造新闻性。

默认交付可直接打开和分享的单页 HTML，内嵌或本地打包必要样式与核心图形，不依赖服务器、登录或远程脚本。用户明确指定 PNG、JPG、图片尺寸或平台时再按要求导出。若内容过多，优先压缩次要信息或将完整细节留在配套报告中，不通过缩小字体硬塞。

## 头部必须给结论

首屏按以下顺序组织：

1. 产品标识、面向客户的栏目名、覆盖日期或资料截止时间；
2. 一至两行核心结论标题；
3. 一句解释结论依据、适用范围或关键条件的副标题；
4. 必要时放 1—3 个真正支撑结论的关键数字。

核心标题写研究判断，不写成栏目名、主题名或期次。不要只写“全球气候跟踪”“数据跟踪第 37 周”“本周天气观察”；可以使用“观测变化／预测修订 + 主要商品含义”或“最重要的区域分化 + 下一验证点”。标题尽量具体到方向、对象和时间窗口，但不能超出证据确定性。

“移动端结论长图”“长图模式”“HTML 版”“模板生成”等词是内部技术或交付描述，不得出现在客户可见的页眉、栏目名、角标或正文。右上角使用自然的产品栏目名，例如“全球气候观察”“气候商品周览”或与本期范围一致的专题名，下一行再放日期；不得为了填满模板而暴露内部模式名。

只有在数字口径清晰、具有代表性且能直接支撑主结论时，才用大数字领衔。预测概率、异常幅度和商品变化不能混成一个醒目数字。证据相互分歧时，结论可以明确写“分歧扩大”“方向尚未确认”以及最有辨别力的触发信号，不能为了传播效果伪造确定性。

## 建议信息结构

根据内容选 2—4 个主体模块，不要求把完整日周报的五层章节逐字搬入：

- **本期判断**：用一张状态卡、对比条或少量指标解释顶部结论；
- **区域变化**：呈现最重要的产区、流域或运输区域差异，并标明观测与预测时段；
- **商品传导**：用简短链路或对照卡说明哪些影响已确认、哪些仍待验证，以及库存、替代供应等缓冲；
- **下一步观察**：列 2—4 个会支持、削弱或推翻当前判断的具体信号。

全球日周报的长图摘要仍应让读者看见全球背景、重要地区差异和商品含义，但可以高度压缩。局部专题长图只覆盖用户问题所需范围。长图中的每张图表服务于一个判断；缺少可靠序列时改用状态卡或对照表，不造装饰性曲线、风险评分或精确地图。

## 视觉系统

使用 [移动端长图模板](../assets/mobile-long-image-template.html) 和 [移动端长图样式](../assets/mobile-long-image.css) 作为基础，替换模板占位内容并按实际模块增删，可按用户提供的正式品牌规范调整。默认采用暖金色视觉体系：暖白底、金色边线及栏目强调、深蓝黑正文，红绿仅在确有方向含义的数据上少量使用。整体语言是细边框圆角卡片、清晰编号、紧凑图表与充足留白；不能把金色铺成大面积高饱和背景而降低阅读对比。不要复制参考图中的第三方 logo、二维码、口号、水印或产品名称；只有用户提供已授权资产和真实目标链接时才加入相应品牌元素或二维码。

- 桌面设计基准宽度使用 1080 px，页面在窄屏自动适配；主要文字在手机浏览器中无需双指缩放即可直接阅读。
- 优先控制在约 2—4 个手机屏；超过 5 个屏或包含大量表格时，优先拆分系列图或改附完整报告。
- 标题、结论数字、模块标题、正文、图注形成清晰的五级层次；同级元素样式保持一致。
- 正文以短句、数字和图表为主，避免把长段落缩小后塞入卡片。表格只保留影响结论的列。
- 颜色表达须同时有文字、符号或线型提示；红绿不单独承担涨跌、风险或状态含义。
- 图表标明单位、期间和数据来源；数据截止时间不能只出现在页尾小字。

## 页尾与归属

页尾至少保留资料截止时间、主要原始来源、产品标识、技能来源、AI 生成性质和适用的风险提示。按 [品牌、技能来源与风险声明](brand-and-disclosure.md) 使用固定文字，不能因长图空间有限而删掉关键归属。完整加强声明可以放在可读的尾部区域；若同时提供完整报告或真实落地页，可在长图保留简短提示并通过已验证链接指向完整声明，但长图自身仍不能完全省略风险提示。

二维码只在目标地址真实、可访问且用户授权加入时生成；渲染后实际扫码验证。没有目标地址时留出可选区域或直接省略，不生成示意二维码。

## 生成与验收

使用 HTML/CSS 与 SVG 等可稳定渲染的方式制作单页文件。核心图形尽量使用矢量元素，避免依赖远程字体、脚本或图片；不得用 AI 图片生成代替数据图表。用户要求图片版时，再从已验收的 HTML 导出 PNG/JPG。输出前完成以下检查：

- 顶部标题单独阅读即可知道本期核心结论，而非只知道产品名和期次；
- 标题、副标题、关键数字、图表和底部结论使用同一批数据与截止时间；
- 在整图视图和手机阅读尺寸各检查一次，无裁切、溢出、重叠、乱码或过小文字；
- 图表图例、单位、日期和来源可读，颜色和箭头没有夸大因果或确定性；
- 品牌来源、AI 生成性质和风险提示存在且不被裁掉；
- 最终交付的是已打开检查过的 HTML 文件；要求图片版时，还要打开检查导出的 PNG/JPG，不能把未渲染的源代码或未经检查的截图称为完成。

交付消息简短说明主结论、覆盖时点并给出 HTML 文件；若同时交付报告，明确长图是其传播摘要。不要在聊天中重复粘贴页面的全部文字。
