# 繁微 Fiona 技术指标监控

## 前置条件与 API Key

本 Skill 依赖 `technical-analysis`、`intraday-monitor` 和 `futures_market_data` 三个 MCP。首次调用前检查当前工具列表；工具缺失时，按 [MCP 工具清单](references/mcp-endpoints.md) 和 `agents/openai.yaml` 只添加缺少的服务。

- `technical-analysis` 和 `intraday-monitor` **需要 API Key**，实际以 `Authorization: Bearer <API Key>` 鉴权。
- `futures_market_data` 当前公开免鉴权，**不需要 API Key**，不要为它配置 `Authorization` 请求头。

API Key 申请：目前暂不支持在线自助申请，请联系繁微对口销售或项目联系人获取。

只在客户端凭证管理区保存真实 API Key，不得写入对话、Skill 文件或版本库。`401`/`403` 时检查需鉴权端点的 API Key 与权限；超时或 transport error 时检查对应 URL 和网络。

围绕“当前处于什么技术状态、证据是否一致、关键位置在哪里、下一步观察什么”组织分析。综合预计算多周期 TA、实际合约盘中状态和原始市场数据；只调用回答问题所需的最少工具，不机械堆叠指标。

本 Skill 中的“价格结构”仅指高低点、区间、缺口、突破和支撑压力等技术图表结构。这里只诊断换月对技术图表的污染；期现基差、期限结构、月间价差、内外盘价差和完整移仓换月分析归 `fiona-price-structure`。

## 选择处理路径

1. **当前单品种或实际合约**：先调用 `intraday_contract_analysis` 确认实际主力、盘中窗口、成交持仓、限定技术指标和关键位；需要多周期背景时再调用 TA 工具。
2. **多周期最新状态或横向筛选**：调用 `futures_ta_cross_section`。全市场先做截面筛选，只对少量候选下钻。
3. **信号何时变化、持续多久或是否反复**：调用 `futures_contract_ta_series`；不得用最新截面推断历史变化。
4. **历史行情、非盘中区间或原始价格验证**：调用交易日、快照、主力或实际合约时序工具。需要确定性价格序列统计时运行 `scripts/analyze_price_series.py`。
5. **波动率背景**：调用 `get_futures_volatility` 获取历史波动率和隐含波动率；当前周期波动使用盘中结果中的 ATR。只在问题涉及波动、突破质量或风险环境时补充。
6. **事件原因**：仅在用户询问异动原因或需要催化验证时调用 `intraday_related_news`；资讯为空时继续完成技术分析，不补造原因。
7. **夜盘、换月或连续图异常**：读取实际合约分钟/日线、主力序列和候选合约快照，按交易时段和底层合约分段验证；不要直接解释连续图上的跳空。
8. **历史时点重建或事件复盘**：冻结截止时间，只读取该时点前已完成的实际合约K线和设置 `end_time` 的 TA series；用原始序列重建当时可见的结构和指标，当前盘中分类只用于事后对照。

具体工具参数、限制和返回语义见 [MCP 工具清单](references/mcp-endpoints.md)。

## 确认对象与口径

- 先识别品种、实际合约或连续序列、分析截止时间、频率和观察窗口；关键信息缺失且会改变结论时才追问。
- 用市场数据工具确认交易日、品种和合约，不凭中文简称猜测代码。
- 区分实际合约与 `888` 连续序列。实际合约用于最新价格、缺口、成交持仓和可执行关键位；连续序列用于跨换月的方向背景和 TA 信号历史。
- 不把连续序列的价格水平直接写成实际合约支撑压力，也不把连续序列称为可交易合约。`intraday_contract_analysis` 中 `daily_technical`、`daily_bars`、`key_levels.previous_day_*` 和 `key_levels.daily_*_20_previous` 来自 `technical_series_contract`；只使用其方向和相对结构作背景，禁止把这些数值列入实际合约关键位。需要实际合约日线关键位时，另查实际合约历史行情。
- 报告工具返回的实际时间、频率、窗口起止和数据质量。30/60/120 分钟窗口按有效交易时间处理，不写成连续自然时钟时间。
- 检查主力换月、数据截断、缺失频率、缓存时点和不同工具的时间差。口径无法对齐时并列说明，不强行合并。
- 分析夜盘时同时使用 `datetime` 和 `trading_date`：把前一自然日晚间但归属下一交易日的K线列入下一交易日；分别比较“上一交易日收盘→夜盘开盘”和“夜盘收盘→日盘开盘”，不要笼统称为“今日开盘跳空”。排除未完成K线后再计算各时段变化。
- 诊断换月时分别检查旧主力、新候选合约的成交量、持仓量、价差及实际序列，并检查主力序列的 `contract` 变化。只有工具明确返回连续序列底层合约、切换日和复权方式时，才能确认某个连续图跳变的生成机制；否则只写“真实合约走势”“换月污染风险”或“未复权切换的情景估算”。单日价格对齐不能证明整个连续序列没有拼接影响。
- 重建历史时点时先确认K线时间戳表示开盘还是完成时点，排除截止时点尚未完成的K线，并保留足够的前置数据供均线和指标预热。自算指标必须说明公式、参数、初始化和样本范围；公式无法与服务端对齐时只作为独立统计，不冒充当时的服务端指标值。
- 在解释指标前检查行情可研究性：最新时间属于当前交易日、主力标识在工具间一致、OHLC有效、成交与持仓非占位、已完成K线中有足够真实成交。`data_quality=ok`、`available=true` 或指标成功计算只表示接口结构可用，不证明行情有效。
- 对大量零成交填充K线、固定价格、零持仓、异常零OHLC或极少成交形成的跳点，优先报告“陈旧/占位数据”或“低流动性噪声”。不要把ATR=0、全中性票、机械均线重合解释为横盘或压缩，也不要给出可执行支撑压力。

## 综合四类证据

按问题裁剪，不要求每次覆盖全部维度。详细判断原则见 [技术分析框架](references/technical-framework.md)。

### 趋势

- 结合价格高低点、均线关系、综合信号和不同周期方向判断趋势、震荡、反弹或回落。
- 将 1m/5m 视为短周期变化，15m/30m 视为盘中结构，60m/1d 视为较高周期背景；根据实际任务调整，不把该分层写成固定预测规则。
- 短周期转向而高周期未确认时写“短周期改善/转弱，高周期仍有分歧”，不要直接升级为反转。

### 动量

- 先看 TA 的综合信号和多空中性投票，再用 SMA、momentum、overlap、pivot 和 candlestick 分类解释信号来源。
- 只在用户明确追问时展开单项指标；不要把几十个指标逐项罗列，也不要按指标数量机械多数表决。
- 结合盘中 MACD、RSI和成交持仓验证动量。中性票占比高或类别相互冲突时降低结论强度。

### 波动率

- 区分 ATR、历史波动率和隐含波动率。ATR描述当前周期绝对波动范围；历史波动率描述已实现波动；隐含波动率描述期权市场的预期波动。
- 波动率上升只表示波动扩张，不等于方向上涨。判断突破质量时同时检查方向、收盘位置、成交活跃度和持仓变化。
- 跨品种比较 ATR 时先转为价格百分比或历史相对位置；不同期限、不同波动率口径不得直接混排。
- 比较多个品种时先固定同一频率、有效交易窗口、数据时点和指标字段，再分别报告“相对强弱”与各自“绝对状态”。HV/IV只在同一交易日、同一期限字段之间横向比较；过期数据只能作历史背景。
- 判断波动压缩时比较同频、等长、已完成K线的滚动真实波幅或标准化ATR，并检查多个相邻窗口，而不是用一个低ATR截面或不等长区间下结论。盘中成交下降还要排除午休前后、开收盘和夜盘切换等时段季节性；缺少同一时段历史基准时降级为“局部收敛”。

### 技术价格结构

- 从实际合约的前高前低、20周期高低点、摆动高低点、区间边界、缺口、均线和 ATR 范围识别支撑压力候选。
- 给出关键位来源和数据时点，不制造伪精确点位。多个相近来源重合时可称为“区域”，并说明其依据。
- 把触及、盘中刺穿、有效突破和突破确认分开。优先使用工具返回的 `breakout_confirmation` 和趋势切换检查项。
- 把“突破确认不足”与“动量背离”分开。成交、持仓或短周期信号未确认只说明证据不足；认定价格—动量背离候选至少需要同一实际合约、同一频率的两个已完成价格摆动峰值，以及对应同口径动量峰值走低。只有最新截面、连续合约分类信号或不同频率指标时，不声称背离。
- 将支撑压力写成观察条件，不写成确定性买卖点。

## 信号一致性、分歧与演变

- 将“多个周期同向”称为多周期一致或共振，但同时检查投票强度、可用频率和实际行情确认；不要转换为上涨/下跌概率。
- 将短周期与高周期相反视为周期分歧，不当作数据错误。说明谁先变化、谁尚未确认。
- 判断“刚刚转强”“持续转强”“频繁反复”时读取 TA series，检查当前方向连续长度和近期切换次数；需要批量计算信号序列时使用临时代码，不凭目测大量记录。价格序列脚本不处理 TA 信号。
- 判断信号扩散时记录各周期首次转向、连续同向根数、首次反向、相邻周期时滞和中性间歇。只有相邻周期按序跟随且维持不止一个孤立信号时才称“扩散得到持续确认”；单根中周期跟随、高周期未参与或短周期反复时写“观察到弱扩散阶段”，即使随后失败也不要升级为高质量信号。
- 区分最新截面状态与历史过程。没有序列证据时只描述“当前状态”。
- 复盘历史突破时用当时的实际合约K线逐根重建越界、收盘保持、成交持仓确认、回踩和回区间过程。当前 `breakout_confirmation` 只描述最新窗口，不作为过去某根K线是否突破的证据。
- 结合窗口涨跌、成交活跃度、持仓和资金判断技术信号是否得到市场行为确认。价格与持仓的组合用于描述新增多头、新增空头、空头回补、多头离场或存量博弈，不用于证明未来方向。

## 执行全市场技术筛选

- 先公开筛选口径，再计算候选；不要在看到结果后静默改变“短周期”“中周期”“确认”或阈值定义。
- 将 TA 连续合约按品种代码与盘中监控的实际主力匹配。报告 TA 可用品种数、盘中可匹配品种数、最终交集数和关键缺失，避免用部分覆盖声称完整全市场结论。
- 检查 `available_count`、各项 `available`、盘中 `scope.contracts` 和数据质量。只在完整交集内判断“没有符合条件的品种”。
- 若严格口径无候选，直接报告“无严格入选”；可以另列接近条件的观察对象，但必须说明放宽了哪一项，不能混入正式结果。
- 综合信号数值是有序分类，不是收益幅度或跨频率可加总分数。筛选后检查多空中性投票，避免把中性票占多数的轻微信号称为强共振。
- 板块分析用市场目录先定义原始样本，再按数据新鲜度和最低流动性形成合格样本；同时报告原始覆盖、今日有效覆盖、排除对象及理由。分别计算价格广度、TA方向广度和量价持仓确认广度，不能用一个板块平均涨跌代替三者。

## 形成后续观察条件

至少在方向性结论中说明：

- **确认条件**：哪些价格结构、周期信号、成交或持仓变化会增强当前判断。
- **失效条件**：哪些关键位失守、信号反向或量价持仓变化会削弱当前判断。
- **主要分歧**：哪些周期、指标类别或数据源尚未一致。
- **数据限制**：连续与实际合约差异、缓存时点、未收盘状态、缺失字段或估算口径。

使用“偏强、偏弱、震荡、改善、转弱、延续、反弹/回落、反转未确认”等条件化表述。只有工具明确返回反转确认且其他关键证据不冲突时，才写“反转信号得到确认”。

## 输出

先回答核心判断，再按问题需要提供：

1. 分析对象、实际合约/连续序列、时间、频率和窗口；
2. 趋势、动量、波动率和价格结构中的关键证据；
3. 支撑压力及其来源；
4. 多周期一致、分歧和信号演变；
5. 后续确认条件、失效条件和数据限制。

保持事实、工具分类和模型归纳相互区分。用户只问一个指标时直接回答，不强制生成完整报告；用户要求综合分析时再覆盖四类证据。

## 边界

- 不把综合信号、指标投票、形态、支撑压力或波动率单独解释成确定的未来收益。
- 不输出自动交易、确定性买卖指令、目标收益、仓位、止盈止损或面向个人持仓的操作建议。
- 不承担期现/期限结构、基本面、研报、套保或回测任务；按问题转交相邻 Skill。
- 不在 MCP 返回为空、延迟或缺失时编造指标、合约、关键位或原因。
- 不把新闻发布时间接近价格变化直接写成因果。只有资讯时间先于行情、机制与品种相关且有独立来源或市场反应证据时，才写“可能相关”；当前资讯工具不能单独证明“导致”。
- 用户要求买卖点时，改为提供技术状态、关键区域、确认与失效条件。
