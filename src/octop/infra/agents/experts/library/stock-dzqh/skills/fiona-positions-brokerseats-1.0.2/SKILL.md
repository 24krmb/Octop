# 繁微 Fiona 会员席位持仓数据

## 前置条件与鉴权

本 Skill 依赖 `futures_market_data` 和 `market_calculate`（部分现有配置名为 `market_data_calculate`）。首次调用前检查 `get_futures_member_positions`、`get_member_position_summary` 等所需工具是否已就绪；工具缺失时，先使用 `agents/openai.yaml` 的依赖声明或对应 MCP 配置只补充缺失项。

`futures_market_data` 和 `market_calculate` 当前公开免鉴权，**无需访问凭证**，不要配置 `Authorization` 请求头。工具不存在时优先判断为 MCP 未配置或未重新加载；超时或 transport error 时检查 URL 和网络。

围绕“谁在做多、谁在做空、结构如何变化”组织分析。以 `futures_market_data` 的 `get_futures_member_positions` 为主接口获取合约×会员×持仓类型的成交量、多空持仓及增减，结合 `market_data_calculate` 的金额口径、会员汇总、品种汇总与建仓过程；按照 [会员持仓分析规范](references/analysis-methods.md) 自行完成排名、集中度、多空比、净持仓等计算，不依赖通用统计 MCP。

## 能力定位

覆盖六类相互关联的证据：

1. **席位多空排名**：某合约某交易日前 N 席位（通常前 5/前 10/前 20）的多头、空头和成交量排名及其占该类型持仓的比例。
2. **席位增减变化**：各席位较上一交易日的增仓、减仓手数，多头、空头、成交量分别观察。
3. **净持仓与方向**：多头持仓减空头持仓的净持仓，净多席位与净空席位，以及按会员汇总的跨合约方向。
4. **持仓集中度**：前 N 席位集中度（CR5/CR10/CR20）、多头与空头集中度的不对称，及其相对上周/上月的变化。
5. **多空结构特征**：前 20 席位多空持仓量比、净持仓合计和增减方向，判断会员席位层面整体偏多还是偏空及其变化。
6. **重点席位跟踪**：指定会员在指定合约上的建仓过程、持仓均价与当日盈亏。

## 工作流程

1. 明确品种或合约范围、截止日期、席位范围（前 5/前 10/前 20）和任务层级。先用交易日历确认实际交易日。
2. 按问题读取 [MCP 工具清单](references/mcp-endpoints.md)，不要机械调用全部工具：
   - 席位排名、集中度：调用 `get_futures_member_positions`，传 `contract` 与 `position_type=2/3`（多头/空头），按 [会员持仓分析规范](references/analysis-methods.md) 本地计算。
   - 席位增减：优先使用接口返回的“变化”字段，必要时取相邻交易日对比。
   - 净持仓：单合约按多空相减本地计算；跨合约或单一会员跨品种用 `get_member_position_summary`。
   - 重点席位建仓：调用 `get_company_contract_opening_process`。
   - 金额口径与席位品种盈亏：调用 `get_member_position_amounts`、`get_company_type_profit`。
   - 会员名称标准化：需要传入会员名称参数时，先用 `get_futures_member_company_names` 获取标准简称。
   - 合约参数与行情：需要合约乘数用 `get_futures_contract_trading_params`；需要结算价/收盘价/全市场持仓量用 `get_futures_timeseries_quotes` 或 `get_futures_snapshot_quotes`。
3. 检查 `start_date`/`end_date`、`as_of_date`、`position_type`、单位（手/元）、合约代码和会员简称。不同日期、合约或口径不得伪装成同一时点。
4. 检查每次返回的 `total`、`returned`、`truncated`、`hint`，确保拿到完整前 20 席位；截断时缩小 symbol/contract/member_name 过滤后再查。
5. 按 [会员持仓分析规范](references/analysis-methods.md) 处理排名、集中度、多空比、净持仓和增减。计算量较大时写临时代码处理，不凭心算批量数据。
6. 先描述席位事实，再解释多空结构含义。将多头、空头、增减方向和集中度贡献拆开，不要把某一席位动作直接等同于市场方向。
7. 输出结论、数据时点、席位证据、变化、结构特征与限制。不把会员持仓结构单独解释成确定的未来涨跌。

## 持仓计算与表述规则

### 数据与口径

- `get_futures_member_positions` 返回“手”，是席位分析主口径；`get_member_position_amounts` 返回“元”，成交额/持仓额 = 数量 × 结算价 × 合约乘数。两者不混用、不合并排名。
- `position_type` 支持 `1/2/3`、`trade_volume/long_position/short_position`、`volume/long/short` 及中文别名（成交量/多头持仓/空头持仓）；留空会一次返回三种类型。
- `get_member_position_summary` 是品种级汇总（跨合约），与单合约净持仓要区分。
- 会员持仓数据只覆盖交易所公布的席位（通常前 20 名），不等于品种全部持仓；需要全市场成交持仓背景时用 `get_type_positions_amount` 或行情接口的持仓量，并说明口径差异。

### 排名

- 只对同一交易日、同一合约、同一持仓类型排名。多头排名按多头持仓量降序、空头排名按空头持仓量降序、成交量单独排名。
- 排名结果同时报告当日值、较上一交易日增减及该席位占该类型持仓的比例。
- 只取前 N 席位时报告 N 和分母口径。默认 `limit=200` 足以覆盖前 20 席位，但仍要核对 `truncated`。

### 增减变化

- 优先使用接口直接返回的“变化”字段，并用相邻交易日原始值复核，防止换月、合约切换或字段口径不同。
- 增仓榜、减仓榜分别按多头/空头/成交量列出。绝对手数与占比不同，大席位和小席位的手数增减不可直接比重要性。
- 区分“当日增减”和“区间累计变化”；连续跟踪时明确是单日还是多日合计。

### 净持仓

- 净持仓 = 多头持仓 − 空头持仓（按量）；净多席位为正值，净空席位为负值。金额口径净持仓额同理。
- 计算某会员对某合约的净持仓时，若该会员只出现在多头或空头榜单中，未出现的那一侧按 0 计算，并在结论中说明该侧未进入榜单、按 0 处理。
- 净持仓反映该席位/会员在该合约/品种上的多空净暴露，不等于观点正确，也不等于价格方向。
- 跨合约汇总时先说明是否合并了不同月份合约，避免把不同到期月份的持仓简单相加。

### 集中度

- 前 N 席位集中度 = 前 N 席位某类型持仓合计 / 该合约该类型会员持仓合计，并报告分母口径。
- 常用 CR5 / CR10 / CR20；多头集中度与空头集中度分别计算并对比，不对称本身就是结构信息。
- 集中度上升/下降要与历史比较（上周、上月或近 N 日序列），单日集中度只描述当前分布。

### 多空结构

- 前 20 席位多空持仓量比 = 多头合计 / 空头合计；也可用净持仓合计。多空比大于 1 表示前 20 席位整体偏多，小于 1 偏空。
- 席位可按默认类别（外资/机构/零售）分组观察多空结构，默认名单见 [会员持仓分析规范](references/analysis-methods.md)；用户自定义时以用户为准。
- 会员持仓结构反映的是席位层面的多空分布，与价格涨跌没有确定因果；不据此给出买卖建议或价格预测。
- 多空结构变化要区分来自新增持仓、减仓还是换手，并指出是某几个重点席位主导还是普遍变化。

### 数据限制

- 交易所席位数据盘后发布，约 17:00 后接口会更新当日新数据；`start_date`/`end_date` 均留空返回数据库中最新可用交易日，报告时标注实际日期。
- 会员名称使用标准简称（`get_futures_member_company_names` 校验），多个用逗号分隔。
- 明细接口是全服务数据量最大的接口，务必先传 symbol 或 contract，再传 member_name / position_type 缩小范围。

## 输出结构

按问题裁剪，通常采用：

1. **结论**：当前会员席位持仓反映的多空结构及最显著变化。
2. **数据时点与口径**：交易日、合约、席位范围、单位（手/元）、position_type、分母口径。
3. **多空排名**：多头前 N、空头前 N、成交量前 N，含占比与增减。
4. **增减变化**：增仓最多与减仓最多的席位，按多/空/成交量分别列出。
5. **净持仓与重点席位**：净多席位、净空席位，以及重点席位的建仓过程与方向变化。
6. **集中度与结构特征**：CR5/CR10/CR20、多空比及其变化。
7. **限制与风险**：盘后发布（约 17:00 后更新）、前 20 席位覆盖范围、口径差异、数据缺失或截断。

不要给出无依据的买卖建议。数据为空或能力尚未接入时说明缺失，不补造排名、席位、净持仓或集中度。

## MCP 与本地计算

使用前读取 [MCP 工具清单](references/mcp-endpoints.md)。不要自行构造 HTTP 请求替代已注册的 MCP 工具；取得原始数据后按照 [会员持仓分析规范](references/analysis-methods.md) 自行写代码计算。

需要确定性地计算排名、集中度、多空比、净持仓和增减时，可运行：

```bash
python scripts/analyze_positions.py analyze --input positions.json --top 20
python scripts/analyze_positions.py net --input member_summary.json --top 20
```

`analyze` 接受 `get_futures_member_positions` 的完整 JSON 或 items 数组；`net` 接受 `get_member_position_summary` 的完整 JSON 或 items 数组。两者只做确定性汇总，不替代对原始数据的核对。
