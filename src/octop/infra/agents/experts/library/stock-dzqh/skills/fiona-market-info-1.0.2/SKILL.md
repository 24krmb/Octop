# 繁微 Fiona 期货市场基础信息

## 前置条件与鉴权

本 Skill 依赖 `futures_market_data`、`futures_ranking` 和 `market_calculate` 三个 MCP。首次调用前检查相关工具是否已就绪；工具缺失时，优先使用 `agents/openai.yaml` 的依赖声明，或按 `templates/` 中对应平台的配置添加缺少的 MCP server。

三个端点当前公开免鉴权，**无需访问凭证**，配置时不要添加 `Authorization` 请求头。首次调用失败时检查 URL、网络和 MCP transport；若未来服务端改为需要鉴权，以最新接入文档为准，不预先要求用户配置凭证。

围绕“品种是什么、合约如何交易、数据是多少、统计口径是什么”组织回答。通过 Fiona MCP 获取可核验的市场基础事实，不把事实查询扩展为行情预测或交易建议。

## 能力定位

覆盖四类客户问题：

1. **品种与交易规则**：品种代码、交易所、板块、可交易合约、交易日历、交易时段和合约参数。
2. **行情与历史数据**：行情快照、指定合约时序、主力合约时序、全市场总成交量和持仓量。
3. **市场统计比较**：板块统计、品种排名、主力横截面变化和时间序列比较。
4. **持仓与资金数据**：品种沉淀资金、资金流向、投机度、会员持仓、仓单、波动率。

本 skill 负责原始基础数据查询、简单事实比较、市场交易结构分析，不负责新闻、研报、机构观点、供需推断、价格结构推断、市场预期研判、价格目标、买卖点和仓位建议。

## 工作流程

### 快速路径（默认）

- **品种/合约/交易日/交易规则** → 仅调 `futures_market_data`（`get_futures_product_info`、`get_futures_trading_calendar`、`get_latest_futures_trading_date`、`get_tradable_futures_contracts`、`get_futures_contract_info_table`、`get_futures_contract_trading_params`）。
- **行情快照 / 历史行情** → `get_futures_snapshot_quotes`、`get_futures_timeseries_quotes`、`get_futures_dominant_quotes`。
- **板块 / 品种排名** → `futures_ranking`（`get_ranking_indicators`、`get_product_ranking`、`get_section_statistics`、`get_dominant_cross_section_change`、`get_symbol_overview`）。
- **资金 / 成交持仓** → `market_calculate`（`get_type_positions_amount`、`get_product_fund_flow`、`get_product_speculation`）。
- **会员 / 波动率 / 仓单** → `get_futures_member_company_names`、`get_futures_member_positions`、`get_futures_volatility`、`get_futures_warehouse_quantity`、`get_futures_warehouse_distribution`。

每个单一数据点直接调对应工具即止；涉及品种/日期标准化或“合约+行情+排名+资金”综合任务时，读取 [完整工作流程](references/full-workflow.md) 按标准化 → 行情 → 统计/计算的顺序组合调用。

## 数据口径与处理规则

### 品种、合约和交易规则

- 品种简称、交易所代码、合约代码和连续合约名称必须分开记录。
- 可交易合约必须对应查询日期；不能用当前合约列表回答历史日期的可交易状态。
- 交易时段要注明交易所、品种、日盘/夜盘和节假日前后的实际口径。
- 合约乘数、最小变动价位、保证金比例或手续费费率等参数以 MCP 返回结果为准，不凭记忆补充。
- 若客户询问一手或某持仓的实际保证金或手续费，可按如下方式计算：一手保证金 = 合约乘数 × 结算价 × 保证金比例；手续费根据收费方式按“固定金额 × 手数”或“成交金额 × 费率”计算，各字段可分别从合约规则、行情快照和交易参数接口取得。

### 行情和历史序列

- 快照、指定真实合约序列和主力合约序列必须区分。
- 主力/连续合约是分析序列，不等同于某一张可直接下单的真实合约。
- 主力切换时保留每天的真实合约代码；跨合约序列不得直接解释为纯价格收益。
- 自然日期、请求日期、实际交易日期和接口更新时间必须分开记录。

### 排名、持仓和资金

- 排名必须说明指标、观察日、排序方向、样本范围、单位和是否完整。
- 会员持仓、资金流和投机度的正负号含义以 MCP schema 为准，不自行改变符号。
- MCP 返回的沉淀资金和资金流向均为品种口径；若客户询问某合约的沉淀资金，需另行计算：合约沉淀资金 = 持仓额 ×（多头保证金比例 + 空头保证金比例），其中持仓额 = 持仓量 × 交易乘数 × 结算价，各字段可分别从 `get_type_positions_amount`、合约规则、行情快照和交易参数接口取得。
- 数据滞后、样本不足、单位不可比或结果截断时，降低结论范围并说明缺口。


## 工具协同与降级

- 不调用 SDK、`finosdk-query` 或自行构造 HTTP 请求替代已注册 MCP。
- MCP 不可用、无权限、返回空结果或覆盖不足时，说明具体失败环节；不得编造实时行情、排名、合约或交易状态。
- 客户同时询问“当前数据”和“后市判断”时，只返回已核验的基础事实，不扩展为预测。
- 客户要求新闻、研报、供需、期限结构、席位集中度或交割压力等超出范围的分析时，说明当前 skill 不覆盖，不假设相关数据或工具已经连接。

## 输出结构

按问题裁剪，通常采用：

1. **结论**：直接回答客户问题。
2. **数据时点与口径**：品种/合约、交易所、实际数据日期、区间、单位和 MCP 工具。
3. **关键结果**：保留原始代码、日期、统计对象和必要的结构化表格。
4. **数据限制**：截断、缺失、权限、滞后或不可比口径。

## 示例问题

- 查询某日期可交易的期货合约，并列出品种、交易所和合约代码。
- 查询某品种的交易参数、最近交易日和指定区间主力行情。
- 比较多个板块或品种的涨跌、成交持仓和资金流排名。
- 查询某品种总成交量、主力会员持仓、仓单情况等，并说明数据口径。
