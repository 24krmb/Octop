# 繁微 Fiona 期货资讯整理

以 Web Search 和网页浏览为主要数据来源回答期货资讯问题，不依赖 Fiona MCP 也必须完整执行。经济日历 MCP 在宏观指标、计划事件和假期问题中可与公开检索并行使用；资讯 MCP 仅作低权重候选线索，通常不必调用。仅在相关 MCP 已可用或用户选择启用时，按 [可选 MCP 接入与工具清单](references/mcp-endpoints.md) 使用。重点提供事件与品种之间的关联、影响路径和证据，不罗列无关新闻。

## 工作流程

1. 明确对象、时间范围和任务类型。用户未指定范围时按 [场景输出指引](references/output-modes.md) 选择默认时间窗；在回答中写明实际覆盖范围、截止时间和时区。
2. 制定检索词。先根据上下文识别品种的标准名称、常见别名、代码、交易所和产业链关系；无法可靠判断或存在歧义时，通过可靠来源核实后再调用 MCP 或扩展检索词，不凭记忆补全、不按字面猜测。
3. 先规划 Web Search 与公开来源。任务涉及宏观指标、计划事件或市场假期，且 `fiona-economic-calendar` 已可用时，可与公开检索并行调用；只有在全市场宽扫描、公开检索召回不足或需要交叉检查时，才按需参考 `fiona-news`。具体边界见 [可选 MCP 接入与工具清单](references/mcp-endpoints.md)。
4. 执行检索并打开可访问的来源页面，核对发布日期、事件时间和正文；搜索摘要或资讯流只用于发现线索。重大事件、事故和规则变化优先寻找官方、一手或多方相互印证的信息。
5. 按事件合并重复和转载内容，区分事件发生时间、首次报道时间和后续更新时间。
6. 研判事件的重要性、相关品种、传导路径、影响方向、期限和不确定性。事实不足时明确说明，不补造原因或影响。
7. 按用户场景组织答案。具体结构见 [场景输出指引](references/output-modes.md)。

## 资讯处理规则

- 先做实体消歧，再判断品种相关性；不要因字面相同把“苹果公司”关联到苹果期货。
- 区分直接影响、产业链影响、替代关系、物流影响、宏观影响和弱相关。
- 将来源事实、媒体观点和模型推断分开表达。
- 不把时间上同时发生的新闻直接认定为行情原因。异动归因应对齐行情启动时间与事件时间，并使用“已确认 / 高度可能 / 可能相关 / 暂无充分证据”表达证据强度。
- 利多或利空判断应说明作用对象、传导路径和时间尺度；同时指出主要反向因素。不要给出确定性价格预测、目标位或交易指令。
- 搜索结果不足以支持“完整覆盖”时，使用“检索到的主要事件”，不要声称已穷尽全部资讯。

## 工具协同

- Web Search 是默认主路径。执行普通资讯、主题研究、事故核查、规则公告或异动归因时，不先检查、不要求安装、也不等待 Fiona MCP。
- 经济日历 MCP 的结构化指标、计划事件和假期数据可作为可靠的并行数据源；涉及政策含义、统计原文或交易安排时继续补充发布机构或其他可靠来源。
- 资讯 MCP 只用于发现可能遗漏的候选快讯。不要仅凭其标签、重要性或正文确认事实、品种相关性、因果关系和影响方向，也不要默认每次调用。
- MCP 未配置、未授权、调用失败、返回为空或覆盖不足时直接继续 Web Search。只有用户明确要求 MCP 数据，或缺失明显影响报告范围时才简要披露，不因可选 MCP 不可用降低普通资讯任务的完成度。
- 查询行情或异动原因时，通过交易所、行情服务或权威财经媒体的公开页面核对；标注报价时间、来源和可能的滞后，无法确认最新时间时不称为实时行情。
- 查询期货规则或公告时，优先检查发布机构的公告列表，再用搜索补充；核对发布日期、生效日期和适用品种。
- 用户要求定时推送早报或晚报时，使用可用的自动化工具负责调度；本 skill 负责生成报告内容。

## 输出要求

- 先给结论和最重要事件，再给证据与影响分析。
- 使篇幅与问题范围、事件数量和重要性相匹配，不设置固定字数、新闻数量或各品种篇幅。重大事件充分说明背景、证据、影响路径、反向因素和后续观察点；次要动态简要交代。
- 回答板块或全市场等综合问题时保证必要的品种与产业链覆盖，不为追求简洁而省略重要信息；没有重大新增动态的部分可以一句话说明。
- 每条重要新闻说明时间、相关品种和入选理由，并在该条末尾直接附 1—2 个可点击来源，格式为 `[来源：机构或媒体名](原文链接)`；优先使用原始文章或公告详情页，不用搜索结果页代替。原文不可访问时可使用完整转载页或权威媒体并标注“转载”或“转引”；没有可靠链接时说明链接不可得，不编造链接。
- 对主题研究和事故核查给出已确认事实、尚未确认事项及后续观察点。
- 对时间敏感内容标注检索截止时间。

## 前置条件与鉴权

本 Skill 安装后可直接使用 Web Search，核心功能 **无需访问凭证**，也不要求配置 Fiona MCP。

用户已获授权并明确希望启用数据增强时，再检查 `news` 和/或 `economic_calendar` 工具是否已就绪；工具缺失时，按 [可选 MCP 接入与工具清单](references/mcp-endpoints.md) 只配置用户选择的服务。这两个可选 MCP **需要 API Key**，实际鉴权使用 Bearer Token，在客户端凭证管理区将服务方提供的 API Key 配置为 `Authorization: Bearer <API Key>`。真实凭证只能进入客户端凭证管理区，不得发送到对话或写入 Skill 文件。
