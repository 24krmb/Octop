# 繁微 Fiona 价格结构数据

## 前置条件与 API Key

本 Skill 依赖 `price_structure`、`futures_market_data` 和 `futures_ranking` 三个 MCP。首次调用前检查当前工具列表；工具缺失时，按 [MCP 接入与工具清单](references/mcp-endpoints.md) 和 `templates/` 只添加缺少的服务。

- `price_structure` **需要 API Key**，实际以 `Authorization: Bearer <API Key>` 鉴权。
- `futures_market_data` 和 `futures_ranking` 当前公开免鉴权，**不需要 API Key**，不要为它们配置 `Authorization` 请求头。

API Key 申请：目前暂不支持在线自助申请，请联系繁微对口销售或项目联系人获取。

只在客户端凭证管理区保存真实 API Key，不得写入对话、Skill 文件或版本库。`401`/`403` 时检查 `price_structure` 的 API Key 与权限；超时或 transport error 时检查对应 URL 和网络。

分析期货价格所处位置，以及期货合约之间、期货与现货之间、不同地区和内外市场之间的相对强弱与结构变化。首次调用 MCP 数据前，必须读取 [MCP 接入与工具清单](references/mcp-endpoints.md)，完成依赖、端点及认证检查；已接入时无需重复配置。取得数据后按照 [统计与结构分析规范](references/statistical-methods.md) 处理序列。

## 数据路由

- 使用 `price_structure` 的 `get_futures_term_structure`、`get_dominant_basis_history`、`get_dominant_basis_market`、`get_product_roll_monitor`、`get_roll_monitor_snapshot` 和 `get_product_roll_history` 分析期限结构、基差和展期；现货或内外盘问题按需调用 `get_product_spot_prices`、`get_cross_market_spread_market`。
- 使用 `futures_market_data` 的交易日、品种、实际合约、快照及主力/实际合约时序工具核对价格、成交量、持仓量和合约身份。
- 使用 `futures_ranking` 的 `get_dominant_cross_section_change` 做全市场主力涨跌和历史位置截面，使用 `get_symbol_overview` 做单品种周期表现与季节性概览。
- 工具的具体用途、限制和失败处理见 [MCP 接入与工具清单](references/mcp-endpoints.md)。根据问题选择必要调用，不机械请求全部服务。

## 工作原则

1. 明确品种或市场范围、截止日期、观察窗口和价格口径。接口需要品种代码或需要确认全市场范围时读取 [期货品种缓存](references/futures-universe.json)。若缓存的北京时间 `updated_at` 距当前日期达到 2 个自然日，且 `get_futures_product_info` 可用，则以空筛选条件、`limit=500` 获取全市场品种；仅在 `truncated=false`、`total=returned` 且关键字段完整时，使用代码、名称、交易所、类型和板块覆盖缓存并更新日期。工具不可用、结果异常或文件不可写时继续使用旧缓存，不中断任务。
2. 检查数据日期、价格类型、单位、币种、规格和合约口径；不同日期或口径不可直接比较。不同工具的日期、主力合约、价格或公式发生冲突时，不拼接成同一结论；优先采用与问题最直接的专门工具并披露冲突。
3. 使用接口返回的派生指标前抽查其与基础字段、公式和单位是否一致。分位应在 0—100 之间，价比应为无量纲；异常条目单列，不纳入计算或排名。
4. 需要计算时按 [统计与结构分析规范](references/statistical-methods.md) 处理数据；批量计算使用代码完成。
5. 先描述价格和结构事实，再分析变化来自哪一条腿及其可能含义；不把单个结构指标解释为确定的未来走势。

## 结构计算与表述规则

### 主力价格状态

- 将方向性价格走势作为结构分析的背景，而不是价格预测。
- 优先使用口径一致的连续序列。窗口跨越主力切换时，识别换月跳点；未经复权的拼接序列不得直接当作纯市场收益。
- 区分“价格水平分位”和“收益率排名”。历史分位必须报告样本窗口、有效样本数和复权口径。
- 将只有上一年同期的一次比较称为“同比”；至少有多个历史同期样本时才称为季节性。

### 期限结构

- 按交割月份排序合约，计算近月减远月的绝对月差和相对月差。近月高于远月通常称为 Backwardation，近月低于远月通常称为 Contango。
- 曲线可能局部倒挂、远端上翘或呈驼峰；不要强迫整条曲线归入单一状态。
- 优先使用 `close`；实时曲线只有 `last` 时标注盘中口径。远月成交不足时降低置信度。
- 不把 Backwardation 机械等同于低库存或利多，也不把 Contango 机械等同于高库存或利空。

### 主力迁移与展期

- 将“目标合约是否准备接替主力”和“换入价格贵不贵”分开判断。流动性分数不是展期成本。
- 使用正式 roll monitor 的成交量、持仓量及其目标/当前比判断切换进度；期限结构曲线中的成交量只作辅助。
- 将 T+1 正式状态与盘中成本估算分开。盘中估算不得覆盖正式状态。
- 沿用正式展期口径：官方展期因子为 `old_main / new_main`；换入成本率为 `new_main / old_main - 1`。

### 期现、地区与内外盘

- 将基差方向写清楚，默认使用“现货减期货”；若接口公式不同，以返回公式为准。
- 分解基差变化来自现货腿还是期货腿。多个现货指标不得随意平均。
- 比较地区价格前，核对日期、品级、规格、含税口径、交货方式、运费和单位；不可比时只并列展示，不计算地区强弱。
- 计算指定现货与主力价差时，先完成现货到期货单位的转换并按共同交易日对齐。
- 将“内外盘价差/价比”与“期现基差”区分。核对汇率、币种、单位、合约月份、交割品级和交易时段后再解释。

## 全市场截面

- **主力价格涨跌与位置**：使用 `futures_ranking` 的主力合约涨跌幅截面对比，按问题选择周、月、近三月、一年或 YTD；需要全市场价格水平分位时同时请求 `percentile_years=1,3`。只对相同截止日且未截断的完整结果排名；分位样本不足、基期缺失、连续零变动或缺乏流动性证据的品种单列。
- **季节性**：使用 `futures_ranking` 的单品种概览。区分价格水平分位与日涨跌幅、基差率、波动率等指标分位，不得混写。
- **展期进度**：调用全市场 roll snapshot，纳入 `inactive` 才能说明全市场状态分布；检查 `total_matched` 与 `truncated`。
- **主力基差**：调用全市场主力基差截面，分别按基差值和可比的基差率观察，不跨单位比较绝对基差。
- **内外盘结构**：调用内外盘价差/价比截面；价差和价比须分开排名，并保留各自公式。

## 输出结构

按问题裁剪，通常采用：

1. **结论**：价格位置与当前最显著的结构特征。
2. **数据时点与口径**：交易日、实时观察时间、主力连续处理、单位和公式。
3. **价格状态**：各窗口涨跌、历史分位及季节性证据。
4. **结构证据**：基差、关键月差、曲线、地区/内外盘价差和移仓流动性。
5. **结构变化**：相对上一交易日、上周、上月或历史同期的变化及由哪条腿驱动。
6. **限制与风险**：换月跳点、T+1、低流动性、数据缺失、口径不可比或截面截断。

不要给出无依据的买卖建议。数据为空或能力尚未接入时说明缺失，不补造价格、排名、合约或状态。
